## ① 用户意图对齐

- **目标受众**：项目评审 / 答辩场合的评委与同学，技术背景混合（含非技术评委）。既要看到 M1–M5 的交付完成度，也要看到 10-22 起新增的热点采集 V2。
- **核心目标**：让观众相信三件事 —— ① 全链路可运行、可演示；② 关键指标可复现，不是自评；③ 真实数据打脸后的设计修正能力（命中率 1.1% 也照实讲）。记住四个数字（100% / 100% / 100% / 0.10s）与「唯一真源」设计哲学。
- **PPT 长度**：14 页（Hero 配额 4 页：01 封面 / 07 架构 / 12 数据 / 14 结束）。
- **视觉调性**：科技工作台、深色封面 + 浅色内容页、数据驱动、克制专业；热点两页用**真实产品截图**作证据，不用示意图替代。
- **内容边界**：必讲 —— 核心闭环、系统架构、热点采集三层模型、推荐流与采纳漏斗、里程碑、四项量化指标、真实难点与修复证据；不讲 —— 代码级实现细节、商业计划、融资。禁碰 —— 把离线 Mock 口径说成「真实 LLM 效果」，把 25.7% 命中率说成稳定值。

## ② 页面布局骨架

- **页面总数与分章**：14 页，**3 章**（比 V1 少一章，把「难点」并入实现验证章收尾，为热点 V2 腾出两页）。
  - 第 1 章 项目概况：P03 扉页 + P04 定位与核心闭环 + P05 功能全景
  - 第 2 章 技术方案：P06 扉页 + P07 系统架构 + P08 热点采集三层模型 + P09 推荐流与采纳漏斗
  - 第 3 章 实现与验证：P10 扉页 + P11 里程碑 + P12 数据与评测成果 + P13 五个真实难点与下一步
- **目录↔扉页契约**：目录声明 3 章 → 全篇有且仅有 3 个 `type: section` 扉页（P03=01 项目概况 / P06=02 技术方案 / P10=03 实现与验证），编号 01–03 连续，标题与页码区间与目录逐字一致。
- **Hero 页定位**：P01（封面）、P07（系统架构）、P12（数据成果，全篇最高潮）、P14（结束页）→ 4/14 = 28.6%，任意两个 Hero 间隔 ≥1 supporting ✓。
- **rhythm 曲线**：peak(01) → valley(02) → transition(03) → valley(04) → valley(05) → transition(06) → peak(07) → valley(08) → valley(09) → transition(10) → valley(11) → peak(12) → valley(13) → peak(14)。无连续 3 页 valley ✓。
- **非对称版式预算**：13/14 页非对称（仅 P14 居中金句对称，用满 1/2 对称预算）。
- **三个扉页版式必须互不相同**：P03 全幅图骑线 / P06 非对称双栏巨型编号 / P10 巨型数字横向铺开 + 纵深线。
