# STORY.md · AI 自媒体内容创作助手项目汇报

## ① 用户意图对齐

- **目标受众**：项目评审 / 答辩场合的评委与同学，技术背景混合（含非技术评委），需同时展示工程完成度与方法论。
- **核心目标**：让观众相信「这是一个全链路可运行、指标可验证、协作方法可复用的完整项目」；记住四个数字（检索 100% / 适配 100% / 一次可用率 100% / 0.10s）与「唯一真源」设计哲学；讲完后认可项目达到计划书全部量化指标。
- **PPT 长度**：14 页（Hero 配额 4 页：01 封面 / 07 架构 / 11 数据 / 14 结束）。
- **视觉调性**：科技工作台、深色封面+浅色内容页、数据驱动、克制专业、巨型数字冲击。
- **内容边界**：必讲——核心闭环、技术架构、M1–M5 实现过程、四项量化指标、难点与应对；不讲——具体代码实现细节、商业计划；禁碰——夸大离线 Mock 口径为「真实 LLM 效果」。

## ② 页面布局骨架

- **页面总数与分章**：14 页，4 章。
  - 第 1 章 项目概况：P03 扉页 + P04 定位闭环 + P05 功能全景
  - 第 2 章 技术方案：P06 扉页 + P07 系统架构 + P08 关键技术
  - 第 3 章 实现过程：P09 扉页 + P10 里程碑 + P11 数据与评测成果
  - 第 4 章 难点与应对：P12 扉页 + P13 难点拆解 + P14 结束页
- **目录↔扉页契约**：目录声明 4 章 → 全篇有且仅有 4 个 `type: section` 扉页（P03=01 项目概况 / P06=02 技术方案 / P09=03 实现过程 / P12=04 难点与应对），编号 01–04 连续，标题与页码区间与目录逐字一致。
- **Hero 页定位**：P01（封面）、P07（系统架构，中段高潮）、P11（数据成果，全篇最高潮）、P14（结束页）→ 4/14 = 28.6%，任意两个 Hero 间隔 ≥1 supporting ✓。
- **rhythm 曲线**：peak(01) → valley(02) → transition(03) → valley(04,05) → transition(06) → peak(07) → valley(08) → transition(09) → valley(10) → peak(11) → transition(12) → valley(13) → peak(14)。无连续 3 页 valley ✓。
- **非对称版式预算**：13/14 页非对称（仅 P14 居中金句为对称，用满 1/2 对称预算）。
- **对称版式预算**：仅 P14 使用 `居中金句` 1 页。
