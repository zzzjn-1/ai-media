# 段落语义分块规范（M2 · T2.2）

> 版本：V1.0.0 ｜ 对应项目计划书 V1.0.0 第三章 3.3.1 + 第四章 4.1.1 + 第五章 T2.2
> 交付物归属：M2 数据与评测基础 → 标注与分块
> 落地脚本：`data/clean_chunk.py`（已对接 M1 `db/app.db` Schema）

## 1. 目标与适用范围
规范素材从「原始文本」到「可向量化分块」的清洗与切分标准，使同一语义单元不被割裂、不同语义单元不被强行合并，为 M3 的 BGE 向量化与 FAISS 检索召回质量打底。适用于 `materials` 入库前的所有文本（docx/txt/md/纯文本导入）。

## 2. 分块原则
1. **语义内聚**：每个分块表达一个完整、自洽的观点或信息点，不跨主题拼接。
2. **段落为单元**：以空行分隔的「语义段落」作为基础切分单元；单个段落对应一个 chunk。
3. **长度上限**：单块字符数上限 `MAX_CHUNK_CHARS = 300`（中文经验值，兼顾向量模型上下文与召回粒度）。
4. **超长再切**：超过上限的段落，按**句边界**（`。！？!?；;`）切分，尽量不截断句子；累加至接近上限再落块。
5. **过碎合并**：长度 `< 15` 字且与上块合并后不超上限的短块，并入上一块，避免碎片化噪声。
6. **保序**：`chunk_index` 从 0 递增，保留原文顺序，便于回溯与展示。

## 3. 清洗规则（执行顺序）
1. 去除 ASCII 控制字符（`\x00-\x08`、`\x0b`、`\x0c`、`\x0e-\x1f`、`\x7f`）。
2. 剥离合成数据标记行（如 `【示例语料·合成数据…】`），仅影响测试语料，真实源无此行。
3. 全角空格 `\u3000` 归一为半角；连续空白折叠为单空格。
4. 折叠超过 2 个的连续空行；去首尾空白。
5. 敏感信息脱敏占位（计划书 2.2.4）：手机号/身份证/邮箱等命中即以 `[REDACTED]` 占位，真实替换在 M3 调用 API 前再做一次。
6. 跨素材内容去重：对清洗后全文做 SHA-256，重复内容跳过入库（避免测试库冗余）。

## 4. 标注字段来源
| 字段 | 来源 | 说明 |
|------|------|------|
| `materials.platforms` | 文件名或导入表单 | 平台标签（weixin/xhs/douyin，逗号分隔） |
| `materials.domains` | 文件名或导入表单 | 领域标签（科技/生活/财经/美妆/教育） |
| `materials.styles` | 文件名或导入表单 | 风格标签（专业/轻松/犀利…） |
| `materials.title` | 自动生成或用户填写 | 素材标题 |
| `material_chunks.content` | 分块结果 | 分块文本 |
| `material_chunks.char_count` | 计算 | 分块字符数 |

> 本 M2 测试库采用「文件名编码元数据」：`{platform}_{domain}_{style}_{seq}.txt`，脚本解析后写入对应标签列。

## 5. 输出格式（对接 M1 Schema）
- `materials`：一行一素材，`content` 存清洗后全文，`chunk_count` 记块数。
- `material_chunks`：每行一块，`embedding` 列**本期留 NULL**，向量由 FAISS 主存储在 M3 构建（计划书 3.1/4.5）；切 Chroma 时启用该列。

## 6. 质量自检（clean_chunk.py 输出）
- 无空块、无超长块（>300 字仅在极端长句下出现，已按句切）。
- 平台覆盖、领域覆盖可打印校验，须满足 M2 验收「≥3 平台 × ≥3 领域」。
- 分块总数与素材数比例合理（本测试库：90 素材 / 270 分块，平均 3 块/素材）。
