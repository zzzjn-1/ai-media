## 三、问题清单（按严重度）

### 🔴 P0-1：计划书 V1.0.0 与 V1.1.0 逐字节相同（版本真实性硬伤）

- **位置**：`AI自媒体内容创作助手项目计划书V1.0.0.docx`、`AI自媒体内容创作助手项目计划书V1.1.0.docx`
- **现象**：两份文件大小均为 **60052 字节**，MD5 完全相同（`bdf50a4bf5aeb63220732a7aed5ea4b0`）。V1.1.0 并未真正升版，内容为 V1.0.0 的复制。

- **影响**：交付物版本可信度受损；若评审以 V1.1.0 为最新版，实际看到的是 V1.0.0 旧内容。

  2. 若 V1.1.0 本无独立修订意图，直接**删除 V1.1.0**，仅保留 V1.0.0，避免误导。

## 七、热点采集 V2 改造记录（2026-10-22）

### 7.2 本次审查发现的实现期缺陷（已在改造中修复）

| # | 缺陷 | 后果 | 修复 |
|---|---|---|---|
| 1 | `init_db.verify()` 在**正式库**上插入自检测试行且不回滚 | 空库启动时 `hotspots` 已有 1 行，种子逻辑误判"已有热点"而跳过注种 → 看板无数据 | verify 末尾显式清理测试行 |
| 2 | `SEED_BATCH` 用 `seed...` 字符串 | 字典序大于 `2026...` 真实批次，聚合按 `MAX(batch_id)` 取"最新快照"时永远取到种子，真实采集被挡住 | 改为纪元时间 `19700101T000000` |
| 3 | 单体 `batch_id` 精确到秒仍可能撞号 | 同一秒的两次采集共用批次，后一批被唯一约束**静默丢弃**（无报错） | 撞号时追加 `-N` 后缀（`_unique_batch_id`） |
| 4 | 库函数假设 `sqlite3.Row` | `data/clean_chunk.py` 用裸连接（tuple 行）时 `dict(row)` 直接崩 | 新增 `_dicts()` 按游标描述符取列，并给脚本连接设 `row_factory` |
| 5 | `hotspots.heat` 无写入来源 | DDL 有列但 signal 层不存原始热度，物化后该列永远 0，前端火焰图标展示失效 | `hot_signals` 增 `best_raw_heat` 列承载 |
| 6 | `hot_collect_log.created_at` 用了 sqlite 的 **UTC** 默认值 | 频控用本地 `datetime.now()` 去减，恒差 +8h，`HOTSPOT_MIN_REFRESH_INTERVAL=60` 永不触发，实测可无限连刷（T-08 实为假通过） | INSERT 显式写本地时间 `_fmt(now)`；修复后连刷正确返回 429 + `retry_after_seconds` |

## 十一、流程上下文持久化（P2-9）审查记录（2026-10-26）

### 11.1 变更性质

**修可用性缺陷**。此前 `FlowContext` 只活在内存里：`taskId` / `topicTitle` / `topicId` / `targetPlatforms` 一旦刷新全部归零，适配页立刻回到「尚无创作任务」，用户刚生成的三版文案无从导出。与 P2-8 的区别是：那次缺的是**读接口**，这次缺的是**前端指针的存活**；两者必须一起有，否则指针在、数据读不回来（或者反过来）。

- **后端**：新增 `GET /api/copy/{task_id}`（只读，不触发优化/适配）。
- **前端**：`FlowContext` 落 `localStorage`（key `flow:v1`，**按账号隔离**，换账号整块丢弃）；生成页 mount 时按持久化的 `taskId` 恢复版本；适配页改为「先读已落库的适配结果，只对缺失平台补适配」。
- **Mock 保真**：`mockCopyTasks` 落 `localStorage`（`mock:copyTasks:v1` + 序号 `mock:copyTaskSeq:v1`），否则离线演示下刷新即失效。

### 11.2 发现并修复的问题

| # | 问题 | 症状 | 处置 |
|---|---|---|---|
| 1 | **Generate 里有同名局部 `taskId`**（`useState(null)`） | 恢复 effect 读的是局部值，永远 null → 一次都没真正发起读取。页面「什么都没恢复」，且因走了早退分支，连日志都不会有 | 删掉局部 state，`taskId` 只从 `FlowContext` 取（持久化的那个指针） |
| 2 | **StrictMode + ref 提前置位 + alive 守卫 = 两边都不干活** | dev 下第一次 mount 的请求被 cleanup 判 `alive=false` 丢弃；第二次 mount 看到「已恢复」标记直接 return，页面永远骨架屏 | 标记改成**成功/失败之后**才置位；`Adapt` 侧在 cleanup 里把 ref 还回去 |
| 3 | **恢复后字段缺一半** | `copy_versions` 没有 `layout_style`/`note`/`truncated` 列，`adapt` 时现算未落库 → 刷新后「排版：短句+emoji+分段」变成「排版：默认」，发布备注整段消失 | 读接口按 `platform_rules` 现算补齐（纯规则无 LLM），`truncated` 用「长度贴平台上限」反推 |
| 4 | **`platforms` 顺序被 SQL 打乱** | 落库顺序是字母序（douyin/weixin/xhs），与用户勾选顺序不一致，前端一旦按它渲染就会「顺序自己变了」 | 按 `task.target_platforms` 重排，未知平台追加在后 |
| 5 | **HTTPException 的 detail 被前端吞掉** | `request()` 只读 `data.msg`，404 一律显示「请求失败 (404)」——用户分不清是任务没了还是服务挂了 | 读 `data.detail`，并把 `status` 挂到 Error 上供调用方判断 |

## 十二、检索口径与评测集漂移审查记录（2026-10-26）

### 12.1 起因

「检索常与选题无关」被记为遗留项，原以为是 BGE 未接入。本轮按「怎么简单怎么来」先量化、再动刀，结果与预期不同：**瓶颈不在向量后端**。

### 12.2 发现与处置

| # | 问题 | 证据 | 处置 |
|---|---|---|---|
| 1 | **评测集与库漂移，命中率假故障** | `api/eval_retrieval.py` 跑出 **0/180 = 0%**；`eval_set.json` 的 `gold_material_ids` 落在 152–241，而当前库素材 id 是 2–91，**交集为 0**（库被重建过，id 重排） | 重跑 `data/build_eval_set.py` 重建 180 条 → 命中率 **180/180 = 100%**；`eval_retrieval.py` 增加**漂移自检**：gold 在库中不存在的任务数 > 0 时告警并提示重建（实测注入 3 条假 gold 可正确触发） |
| 2 | **offline 哈希向量被当成语义向量用** | offline 是「字符 2-gram 哈希 + 随机符号」dim=256，270 块语料下碰撞严重；粗排 Top-40 只覆盖语料 15%，候选池≈随机抽样，重排再准也救不回 | `rag_pipeline.retrieve()` 在非 bge 后端改为**全量召回 → 重排**（领域过滤优先，同领域为空自动放宽）；实测单次 **9ms**，退化为确定性排序 |
| 3 | **BGE 加载失败会让整个服务起不来** | 实测 `SentenceTransformer("BAAI/bge-large-zh")` 在无 `HF_HUB_OFFLINE=1` 时联网校验被出站代理打成 **502** → `EmbeddingService.get()` 抛异常 → `/api/health` 都 500 | `EmbeddingService.__init__` 加 try/except：失败**回落 offline**，并把真实后端如实上报 `/api/health` 的 `embedding_backend`（不再谎报 bge） |

### 12.3 数据：BGE 值不值得默认开（实测结论：暂不开）

| 指标 | offline 全量召回 | BGE 粗排40（dim=1024） |
|---|---|---|
| 真实选题标题 Top-5 查询二元组覆盖率 | 0.01 | 0.01 |
| 评测集查询 Top-5 覆盖率 | 0.28 | 0.28 |
| 同领域占比 | 0.50 / 1.00 | 0.50 / 1.00 |
| 首次加载 | 0s | **27.9s** |
| 编码 270 块（CPU） | ~0s（哈希） | **59.2s** |

原因：**语料侧没有可检索的语义**。90 篇语料是「大模型 / 算力 / 端侧推理」模板句，与「iPhone Duo 翻车」「油价传导」这类真实标题的二元组重合≈0；换更强的 embedding 也检索不出不存在的内容。

结论：BGE 保持「可选、不默认」。真要提升相关性，下一步应换**真实往期文案语料**（`data/corpus/`），而不是换向量后端。脚本：`项目汇报/_smoke/eval_bge_vs_offline.py`、`eval_retrieval_offline_ab.py`。
