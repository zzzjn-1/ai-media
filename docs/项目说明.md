# 项目说明 · AI 自媒体内容创作助手

> 版本：V1.0.0 ｜ 日期：2026-10-12
>
> 一站式自媒体内容生产工作台：**素材库 + 热点追踪 → 选题策划 → RAG 文案生成（≥3 版本）→ 风格优化 → 多平台适配 → 导出**，覆盖微信公众号 / 小红书 / 抖音三大平台。

---

## 1. 项目概况

| 项 | 内容 |
|---|---|
| 产品形态 | Web 工作台（前端展示 + 后台管理一体，JWT 鉴权） |
| 核心闭环 | 热点推荐流（按账号领域排序）→ 选题列表 → 文案生成对比（SSE 流式）→ 平台适配预览 → 导出 txt/docx |
| 覆盖领域 | 科技 / 生活 / 财经 / 美妆 / 教育（词表唯一真源见 `frontend/src/api/types.ts` 的 `DOMAINS`） |
| 覆盖平台 | 微信公众号（`weixin`）/ 小红书（`xhs`）/ 抖音（`douyin`） |
| 内容风格 | 专业 / 轻松 / 犀利 |
| 演示账号 | `demo_seed` / `Demo@2026`（种子账号；前端 Mock 模式任意账号密码可登录） |

## 2. 技术栈

| 层 | 技术 |
|---|---|
| 后端 | Python 3.10+ / FastAPI / SQLAlchemy 风格 sqlite3 / FAISS / APScheduler / PyJWT |
| 检索 | 两阶段检索：FAISS 粗排（RECALL_TOP_K=40）→ 规则重排（同领域 +0.15 / 同风格 +0.12）→ Top-5；可选 BGE 向量与 BGE-reranker |
| 生成 | OpenAI 兼容 LLM（留空走 Mock 模板）；LangChain LCEL 编排提示词；SSE 流式推送 |
| 安全 | 敏感字段 Fernet 加密落库（`enc:` 前缀），密钥 `DB_FIELD_KEY` |
| 前端 | React 18 + TypeScript + Vite + Ant Design 5 + Tailwind CSS（preflight 关闭） |
| 工程 | 路由级懒加载 + vendor 拆包；`tsc --noEmit` + `vite build` 门禁 |

## 4. 快速开始

### 模式 A：纯前端演示（无需后端，30 秒）

```bash
cd frontend
npm install
# frontend/.env 已含 VITE_USE_MOCK=true
npm run dev        # http://127.0.0.1:5173，任意账号密码登录
```

### 模式 B：全链路开发（真实后端）

```bash
# 1) 后端
python -m venv .venv && source .venv/bin/activate
pip install -r api/requirements.txt
python db/init_db.py && python data/clean_chunk.py --reset
uvicorn api.main:app --port 8000

# 2) 前端（另开终端）
cd frontend
# 将 .env 的 VITE_USE_MOCK 改为 false
npm run dev        # /api 经 Vite 代理到 127.0.0.1:8000
```

### 模式 C：生产部署

```bash
cd frontend && npm run build          # 产物 dist/
# 后端常驻 + Nginx 反代，详见 docs/部署运维手册.md
```

## 7. 关键约定（改动前必读）

1. **领域词表唯一真源**：`frontend/src/api/types.ts` 的 `DOMAINS`。新增领域只改这一处——前端筛选下拉与 Mock 数据自动覆盖；**真实后端**还需补 `data/corpus/` 语料并重跑 `clean_chunk.py --reset`，否则筛选为空。
2. **平台码**：`weixin` / `xhs` / `douyin`，前后端均传码不传中文名。
2.1 **热榜来源码 ≠ 发布平台码（易混淆，务必分清）**：`hotspots.platform` / `HOT_SOURCES` 是**热榜来源**（`weibo/zhihu/baidu/douyin/bilibili/toutiao`），`platform_rules.platform` / 前端 `PLATFORMS` 是**发布平台**（`weixin/xhs/douyin`）。两者语义不同，**禁止复用同一个常量**；`douyin` 两边都出现但含义不同。
2.2 **热点三层模型**：`hot_raw_items`（追加式原始层，跨平台同名各自保留）→ `hot_signals`（聚合层，跨源同话题合并 + 0-100 归一化热度 + 生命周期）→ `hotspots`（物化宽表，F2 按 domain 读取）。改动时**不要**在 raw 层做跨源合并，也不要在 signal 层保留同话题多行。
2.3 **热点配置键**：`HOTSPOT_SCHED_ENABLED`（旧 `HOTSPOT_ENABLED` 已废弃）、`HOT_SOURCES_ENABLED`、`HOTSPOT_API_BASE` 等见根目录 `.env.example`；**每源采集间隔在 `api/core/hot_sources.py` 的 `SOURCES` 注册表**，不在 config。
3. **领域 × 风格**：素材/热点/人设/选题统一使用 `科技/生活/财经/美妆/教育` × `专业/轻松/犀利`，禁止自造词。
4. **密钥**：`DB_FIELD_KEY`（`.env`）一旦设定不得更换，否则历史密文不可解密。
5. **离线口径**：无 LLM Key / BGE 时，检索退化为标题 LIKE、生成为 Mock 模板——预期行为，接 Key 后同脚本复测即验收。

## 8. 已知限制

- 无语义向量时素材正文不可检索（加密无法 LIKE），需 `EMBEDDING_BACKEND=bge`；
- 移动端未做专项布局（侧边栏固定 232px）；
- 热点采集已接真实源（多适配器），但**免费源存在限频/结构变更/间歇 502 风险**：单源失败被隔离并进入退避，看板降级展示库内数据并标注 `degraded`；生产建议配 `HOTSPOT_API_BASE` 指向自托管实例；
- 热点领域判定基于 `api/core/domain_keywords.py` 关键词表，未命中落「综合」且不进 5 个官方领域筛选——词表覆盖不足会表现为"某领域热点偏少"，调词表即可；
- 真实热榜的**垂类命中率天然偏低**（2026-10-22 实测 25.7%，2026-10-26 实测 93 条仅 1 条），绝大多数是时政/体育/娱乐。推荐流默认不推「综合」（合规 + 相关性），因此**某些天「为你推荐」只有一两条**——这是真实情况而非故障，页面会给提示与「全部」入口；
- 「建议角度」由 LLM 惰性生成（单次上限 5 条）：**未配 `LLM_API_KEY` 时退化为规则模板句**（仍可用但生硬），配 Key 后为具体角度；LLM 空返回/解析失败会进入短/长冷却并自动兜底，日志 `[热点建议]` 可查；
- **采纳率在小样本下不可读**：`ctr = adopt / 曝光条数`，单账号、单日只有几十次曝光时，1 次点击就是 5%~25% 的波动——先用它看**趋势**（本周 vs 上周），不要用单日数字下结论。演示库里的数值来自本人操作，不代表真实用户；
- 曝光由前端**渲染后**上报，因此「接口被调用但页面没渲染」（如直接 curl）不计入分母，这与真实产品的曝光口径一致，但意味着自动化压测不会污染指标；
- Mock 模式数据存在浏览器内存，刷新即重置；**唯一例外是「已用过」标记**（落 localStorage），因为真实后端把这个状态存在库里、刷新照样记得，Mock 若也「失忆」会被误当成 bug。曝光计数不落盘（纯统计）。
