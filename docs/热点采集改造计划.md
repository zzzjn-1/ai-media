# 热点采集改造计划（接入「今日热榜」+ 手动采集）

> 状态：方案分析稿（待评审，未实现）
> 目标：把当前"内置 mock + 后台周期自动采集（实际不刷新）"改为 —— 接入真实的「今日热榜」多平台数据源，并把采集方式改为**用户在前端点「采集热点」按钮主动触发**，可自选**平台**与**采集范围（top N）**。

---

## 0. 目标与范围

- **做什么**
  1. 数据源从写死的 mock 切换为真实「今日热榜」（聚合 微博 / 知乎 / 百度 / 抖音 / B站 / 头条 等几十个平台）。
  2. 热点看板新增：**平台多选** + **采集范围 top N（3/5/10/20）** + **「采集热点」按钮**，用户主动触发，不再后台静默周期刷新。
  3. 后端新增手动采集端点，支持按所选平台 + top N 拉取、入库、去重/更新。
- **不做（本期）**
  - 不做真实热度的持续滚动监控（只做"按需拉一次"）。
  - 不做热点→领域的自动分类模型（真实热榜按平台而非内容领域划分，见 §3.6）。

---

## 1. 数据源选型与实测结论

**「今日热榜」对应的是开源聚合项目 DailyHot（imsyy）**，它本身就聚合了几十个平台（微博/知乎/百度/抖音/B站/头条/豆瓣/虎扑/36氪…），与需求"里面有各个平台的热点排行"完全吻合。

**实测关键结论（2026-10-14，沙箱直连）**：
- 公有演示站 `https://hot.imsyy.top/weibo` **返回的是前端 SPA 首页 HTML（被 Cloudflare 拦截/前端路由接管），不是 JSON**。所以不能直接硬编码该域名当 API 用。

**因此推荐落地方式（三选一，建议首选 A）**：
- **A. 自托管 DailyHot API（推荐）**：项目 MIT 开源，支持 Vercel / Cloudflare Workers 一键部署。部署后拿到你自己的干净 JSON 端点，国内可达、稳定、可控。接口形态：`GET {你的实例}/{platform}` → `{ code, name, title, data:[ { title, desc, hot, url, ... } ] }`。
- **B. 配置 `HOTSPOT_API_BASE` 指向任意可达的 DailyHot 风格镜像/实例**：代码保持 DailyHot 解析逻辑，端点地址外置到 `.env`，随时可换。
- **C. 兜底免费 JSON 源**（若 A/B 暂不可行）：`vvhan` / `tenapi` / `60s` 等按平台提供干净 JSON（如 `https://api.vvhan.com/api/hotlist/wbHot`、`https://tenapi.cn/v2/weibohot`），国内可达、无需鉴权。需为这些源各写一个小适配器（结构略有差异）。

> 计划默认按 **A/B（DailyHot 风格）** 实现解析层，并预留 **C（多适配器）** 的扩展点。端点地址通过 `HOTSPOT_API_BASE` 配置，部署时再填。

## 2. 总体方案（前后端改动一览）

```
前端 Hotspots.tsx
  ├─ 平台多选 chips（微博/知乎/百度/抖音/B站/头条…）
  ├─ 采集范围选择（top 3 / 5 / 10 / 20）
  ├─ 「采集热点」按钮 ─POST /api/hotspots/collect {platforms, top_n}─┐
  └─ 看板列表（按 platform 过滤 + 原有 domain 过滤）                  │
                                                                     ▼
后端 routers/hotspots.py
  ├─ POST /collect  → 调 hotspot_sources 拉取 → upsert 入库 → 返回采集数
  └─ GET  /hotspots  → 增加 platform 过滤参数
                                                                     ▼
后端 hotspot_sources.py（新增）
  ├─ 平台注册表（route↔中文名）
  ├─ fetch_platform(platform, top_n) → 解析、切片、归一化
  └─ 超时 / 单平台失败隔离 / 部分成功
```

## 3. 后端改动清单

### 3.1 `api/config.py` 新增配置
- `HOTSPOT_API_BASE`：默认留空（运行时填你的 DailyHot 实例；为空则回退到兜底源）。
- `HOTSPOT_AUTO_COLLECT`：默认 `false`（**关闭后台周期采集**，改为手动）。
- `HOTSPOT_TIMEOUT`：单平台请求超时，默认 `8s`。
- `HOTSPOT_DEFAULT_TOP_N`：默认 `10`，合法值 `[3,5,10,20]`。

### 3.2 新增 `api/core/hotspot_sources.py`
- **平台注册表**：`PLATFORMS = { "微博":"weibo", "知乎":"zhihu", "百度":"baidu", "抖音":"douyin", "哔哩哔哩":"bilibili", "今日头条":"toutiao", "豆瓣":"douban", "虎扑":"hupu", "36氪":"36kr", ... }`（可增删，前端据此渲染选项）。
- `fetch_platform(route, top_n)`：用 `httpx`（已装 0.28.1）GET `{HOTSPOT_API_BASE}/{route}`，解析 `data[]`，取前 `top_n` 条，归一化为统一结构 `{title, summary, url, heat(int), platform(中文名), source("今日热榜")}`。
- 健壮性：单平台超时/异常**隔离**，不影响其他平台；返回 `(items, error)`。
- 兜底：若 `HOTSPOT_API_BASE` 为空或失败，可切换 C 类适配器（本期至少预留结构）。

### 3.3 `api/routers/hotspots.py`
- 新增 `POST /api/hotspots/collect`，请求体 `{ platforms: string[], top_n: int }`：
  - 校验 `platforms` 在注册表内、`top_n` 在合法集合（否则 400）。
  - 并发/顺序拉取所选平台 → 汇总 → **upsert** 入库。
  - 返回 `{ ok, collected, by_platform:{平台:条数}, failed:[平台…] }`。
- `GET /api/hotspots` 增加 `platform` 过滤参数（保留 `domain` 过滤）。

### 3.4 数据库迁移 `db/schema.sql` + `init_db.py`
- `hotspots` 表新增列 `platform TEXT`（采集来源平台，如"微博"）。
- 兼容旧库：在 `init_db.build()` 或启动时对已有 `app.db` 执行 `ALTER TABLE hotspots ADD COLUMN platform TEXT;`（仅当列不存在）。`dedup_hash` 唯一约束保持不变。
- 索引补 `idx_hotspots_platform ON hotspots(platform, is_active)`。

### 3.5 关闭后台自动周期采集 `api/main.py`
- `start_scheduler()` 当前无条件启动 APScheduler 间隔任务（默认 60 分钟）。
- 改为：**仅当 `HOTSPOT_AUTO_COLLECT=true` 才挂间隔任务**；默认不挂。保留 `seed_if_empty()` 仅作为"库空时灌入离线示例"的可选项（默认保留，保证看板首屏不空）。
- 手动采集完全不依赖调度器，端点随时可用。

### 3.6 去重逻辑：INSERT IGNORE → UPSERT
- 当前 `collect_once` 用 `INSERT ...` + 唯一约束回滚做"去重跳过"，因为 mock 不变所以没问题。
- 真实数据会变（热度、排名、url），改为 `INSERT ... ON CONFLICT(dedup_hash) DO UPDATE SET heat=excluded.heat, url=excluded.url, collected_at=excluded.collected_at, is_active=1, platform=excluded.platform`。
- **领域(domain)处理**：真实热榜不按内容领域划分，采集项 `domain` 统一置 `"综合"`，使其出现在"全部"标签下；原有 5 个领域标签仍只展示对应素材热点，互不干扰。看板主过滤改为 **platform**，domain 作为次级过滤保留。

## 4. 前端改动清单（`frontend/src/pages/Hotspots.tsx` 等）

### 4.1 采集控制区（新增，置于标题下/过滤栏上方）
- **平台多选**：用 Ant Design `Tag`/多选 chips 渲染 `PLATFORMS` 中文名（建议固定展示 8–10 个常用平台，可"全选"）。
- **采集范围**：`Select` 或分段按钮，选项 `3 / 5 / 10 / 20`，默认 `10`。
- **「采集热点」按钮**：点击 → `loading` 态 → `POST /api/hotspots/collect` → 成功后 `message.success(`已采集 N 条（平台：…）`)` → 自动刷新列表。

### 4.2 列表展示增强
- 每张卡片新增**平台标签**（如"微博"），与现有领域标签并列。
- 标题可点击跳转 `url`（新窗口打开）。
- 显示采集时间、热度（保持现有火焰图标）。
- 排名：按返回顺序或 heat 排序展示序号（体现 top N）。

### 4.3 过滤逻辑
- 主过滤：**platform**（替换/补充现有 domain 胶囊）。
- 保留 domain 过滤（默认"全部"），二者可叠加。

### 4.4 `frontend/src/api/types.ts`
- `Hotspot` 接口新增 `platform?: string`。

### 4.5 Mock 模式兼容（`frontend/src/api/mock.ts`）
- 新增 `mockCollect({platforms, top_n})`：向内存 store 注入 N 条伪造热点（带 platform），使演示模式下按钮也可用；或简单提示"演示模式：请连接真实后端以采集实时热点"。建议实现前者，保持演示连贯。

## 5. 实施步骤（按依赖排序）

1. **定数据源**：确认采用 A（自托管 DailyHot）/ B（配置镜像）/ C（兜底源）；拿到 `HOTSPOT_API_BASE` 或写好兜底适配器。（前置，阻塞后续解析层）
2. **config.py**：加 `HOTSPOT_API_BASE / HOTSPOT_AUTO_COLLECT / HOTSPOT_TIMEOUT / HOTSPOT_DEFAULT_TOP_N`。
3. **hotspot_sources.py**：平台注册表 + `fetch_platform` + 归一化 + 超时/隔离 + 兜底（对应步骤 1 的源）。
4. **schema 迁移**：`hotspots` 加 `platform` 列 + 索引；`init_db.py` 兼容旧 `app.db` 的 ALTER。
5. **routers/hotspots.py**：`POST /collect` + `GET` 增加 `platform` 过滤 + upsert。
6. **main.py**：`HOTSPOT_AUTO_COLLECT=false` 默认不挂间隔任务；保留可选 seed。
7. **前端 types.ts / mock.ts**：加 `platform` 字段与 `mockCollect`。
8. **前端 Hotspots.tsx**：平台多选 + top N + 采集按钮 + 列表平台标签/链接 + 过滤改造。
9. **文档同步**：`README.md` / `项目说明.md` 更新热点采集为"手动 + 真实源"；`.env.example` 加新配置项；`docs/产物审查报告.md` 记一笔改造。
10. **联调验证**（见 §7）。

## 6. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 公有 DailyHot 演示站返回 SPA 非 JSON | 不硬编码公有站；走自托管/镜像（A/B），端点外置 |
| 免费源不稳定/限速 | `HOTSPOT_TIMEOUT` 超时 + 单平台失败隔离 + 部分成功返回；C 类多适配器兜底 |
| 国内访问海外实例慢 | 优先国内可达镜像或自托管在国内节点；前端按钮带 loading 与失败提示 |
| 真实热榜与 5 内容领域不对齐 | 采集项 `domain="综合"`，看板以 platform 为主过滤，domain 次级，互不污染 |
| 旧 `app.db` 缺 `platform` 列 | 启动时 ALTER 兼容；或 `clean_chunk.py --reset` 重建 |
| 重复采集刷屏 | `dedup_hash` + upsert 只更新热度/时间，不产生重复行 |

## 7. 验证方案

- **单元/接口**：`curl -X POST localhost:8000/api/hotspots/collect -d '{"platforms":["微博","抖音"],"top_n":5}'` → 断言返回 `collected>0`、`failed` 为空或明确列出。
- **去重/更新**：重复采集同平台同 top_n → 数据库行数不增长，但 `heat/collected_at` 更新（upsert 生效）。
- **过滤**：`GET /api/hotspots?platform=微博` 只返回微博项。
- **前端**：打开热点看板 → 选平台 + top N → 点采集 → 卡片出现平台标签与可点击链接 → 空状态/失败均有提示。
- **关闭自动**：确认后端启动日志**不再**出现"热点采集已启动，周期 60 分钟"（除非显式开 `HOTSPOT_AUTO_COLLECT=true`）。

## 8. 需要你确认的几点

1. **数据源走哪条**：A 自托管 DailyHot（推荐，需你部署一次）/ B 填一个可达镜像 / C 直接用免费兜底源（vvhan/tenapi/60s）。这决定解析层写哪种适配器。
2. **默认展示哪些平台**：建议首批固定 8–10 个（微博/知乎/百度/抖音/B站/头条/豆瓣/虎扑/36氪…），是否就按这个，还是你指定清单？
3. **采集范围默认与可选项**：默认 10，选项 3/5/10/20 是否合适？
4. **旧库处理**：直接 `ALTER` 兼容现有 `app.db`，还是你倾向于 `clean_chunk.py --reset` 重建（会清空现有 demo 热点与素材）？
