## 1. 系统组成

| 组件 | 技术 | 运行形态 | 默认端口 |
|---|---|---|---|
| 后端 API | FastAPI + uvicorn | 常驻进程 | 8000 |
| 前端 | React + Vite 构建产物 | Nginx 静态托管（生产）/ Vite dev server（开发） | 80 / 5173 |
| 数据库 | SQLite（`db/app.db`） | 文件型，随后端进程读写 | — |
| 向量索引 | FAISS（`db/faiss.index` + `faiss_meta.json`） | 后端启动时按签名自动校验/重建 | — |
| 定时任务 | APScheduler（热点采集） | 内嵌后端进程 | — |

## 2. 环境准备

### 2.1 硬件与操作系统

- 最低：2 核 CPU / 4GB 内存 / 5GB 磁盘；启用 BGE 向量建议 ≥8GB 内存（权重约 1.3GB）。
- 操作系统：Linux（生产推荐）/ Windows / macOS（开发）。本文命令以 Linux 为准，Windows 见备注。

### 2.2 Python 后端

```bash
# 要求 Python ≥ 3.10
python3 -m venv .venv && source .venv/bin/activate
pip install -r api/requirements.txt
```

`requirements.txt` 分两层：
- **核心必需**（fastapi/uvicorn/faiss-cpu/pydantic/cryptography/python-multipart/apscheduler/pyjwt）——离线可运行，检索为标题 LIKE 兜底、生成为 Mock 模板；
- **语义增强**（sentence-transformers/langchain）——装好即启用 BGE 向量与 LangChain 编排；`EMBEDDING_BACKEND=offline`（默认）时不装也能跑通全链路。

### 2.3 Node 前端

```bash
node -v   # 要求 ≥ 18
cd frontend && npm install
```

### 2.4 目录与权限

- `db/`（app.db、faiss 索引、`.key`）与 `.env` 需对后端运行账户可读写；`.env` 权限建议 `600`。
- 日志目录 `logs/`（自建，见 5.3）。

## 3. 配置项

### 3.1 根目录 `.env`（敏感项，勿入库）

| 键 | 说明 | 默认 |
|---|---|---|
| `DB_FIELD_KEY` | 字段加密主密钥（Fernet）。**丢失=历史密文数据全部不可解密**，务必备份 | 无（缺失时后端无法加解密） |

### 3.2 后端环境变量（`api/config.py`）

| 变量 | 说明 | 默认 |
|---|---|---|
| `DB_PATH` / `FAISS_INDEX_PATH` / `FAISS_META_PATH` | 数据与索引路径 | `db/app.db` 等 |
| `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL` | OpenAI 兼容接口；留空走 Mock 生成 | 空 / api.openai.com / gpt-4o-mini |
| `LLM_TEMPERATURE` / `LLM_MAX_TOKENS` | 生成参数 | 0.8 / 1400 |
| `EMBEDDING_BACKEND` | `offline`（n-gram 哈希）\| `bge` | offline |
| `EMBEDDING_MODEL` / `EMBEDDING_DIM` | BGE 模型 / 向量维度 | BAAI/bge-large-zh / 256 |
| `HF_ENDPOINT` | HuggingFace 镜像（国内） | https://hf-mirror.com |
| `RECALL_TOP_K` / `RERANK_TOP_K` | 召回深度 / 重排输出数 | 40 / 5 |
| `RETRIEVAL_DOMAIN_FILTER` | 粗排阶段同领域软约束 | true |
| `RERANK_STRATEGY` | `lexical`（零依赖）\| `cross`（BGE-reranker）\| `off` | lexical |
| `JWT_SECRET` / `JWT_EXPIRE_HOURS` | 登录令牌secret与有效期（小时） | 开发默认值（**生产必须改**）/ 72 |
| `HOTSPOT_ENABLED` / `HOTSPOT_INTERVAL_MINUTES` | 热点定时采集开关/间隔 | true / 60 |
| `CORS_ORIGINS` | 允许跨域源，逗号分隔 | `*`（生产应收敛为前端域名） |

### 3.3 前端 `frontend/.env`

| 键 | 说明 | 默认 |
|---|---|---|
| `VITE_API_BASE` | API 基址；dev 经 Vite 代理 `/api → 127.0.0.1:8000`，生产由 Nginx 反代 | `/api` |
| `VITE_USE_MOCK` | `true`=纯前端演示（不连后端）；`false`=连接真实后端 | true（**生产必须 false**） |

## 4. 数据初始化（首次部署 / 重建）

```bash
# 1) 建库（schema + 演示账号 + 平台规则 + 热点种子）
python db/init_db.py

# 2) 语料入库：清洗 → 分块 → 加密落库（--reset 清空重建）
python data/clean_chunk.py --reset

# 3) 评测集（可选，供 M5 评测脚本使用）
python data/build_eval_set.py
```

- 语料来源 `data/corpus/{platform}_{domain}_{style}_{seq}.txt`（5 领域 × 18 篇 = 90 篇），可用 `data/_gen_corpus.py` 重新生成；FAISS 索引无需手动构建——后端启动时自动校验签名（分块数/最大 id/维度），过期即重建。
- 重新入库后**必须**让后端重启或触发一次检索以重建索引；旧索引不会导致错误结果（签名不匹配即弃用），但会浪费一次重建时间。

## 5. 启动与停止

### 5.1 开发模式

```bash
# 终端 1：后端
source .venv/bin/activate
uvicorn api.main:app --reload --port 8000

# 终端 2：前端
cd frontend && npm run dev     # http://127.0.0.1:5173
```

### 5.2 生产模式

```bash
# 后端（多 worker 注意：SQLite 写场景建议 1–2 worker）
source .venv/bin/activate
nohup uvicorn api.main:app --host 127.0.0.1 --port 8000 \
  > logs/backend.log 2>&1 & echo $! > logs/backend.pid

# 前端
cd frontend && npm run build   # 产物 dist/，交 Nginx（见第 6 章）
```

停止：`kill $(cat logs/backend.pid)`（优雅退出）；强制：`kill -9`。

### 5.3 日志

- 后端：stdout 重定向至 `logs/backend.log`（uvicorn 访问日志 + 应用日志 + 索引重建记录 `rebuilt index: N vectors`）。
- 前端：Nginx `access.log` / `error.log`。
- 轮转（Linux）：`logrotate` 配置 `logs/backend.log`，按日切割保留 14 天。

### 5.4 健康检查

```bash
curl -s http://127.0.0.1:8000/api/health
# 期望：{"ok":true,...,"counts":{"materials":90,"material_chunks":270,"hotspots":10,...}}
```

counts 与 `db/app.db` 实际行数不一致 → 索引或库被外部改动，重启后端触发重建后复查。

## 6. 生产部署（Nginx）

```nginx
server {
    listen 80;
    server_name your.domain.com;

    # 前端静态产物
    root /var/www/ai-content-studio/frontend/dist;
    location / {
        try_files $uri $uri/ /index.html;   # SPA 历史模式回退
    }

    # 后端反向代理
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        # SSE 流式生成必须关闭缓冲，否则 /api/copy/generate 收不到增量事件
        proxy_buffering off;
        proxy_read_timeout 300s;
    }

    gzip on;                                   # 文本资源压缩
    gzip_types text/css application/javascript application/json image/svg+xml;
}
```

要点：
1. `proxy_buffering off` —— 否则 SSE 文案生成被缓冲成「一次性返回」，实时进度丢失；
2. `try_files ... /index.html` —— react-router 历史模式刷新子路由不 404；
3. 静态资源带 hash 文件名，可设长缓存（`expires 1y` 仅对 `/assets/`）。

## 7. 备份与恢复

| 对象 | 频率 | 方式 | 恢复 |
|---|---|---|---|
| `db/app.db` | 每日 | `sqlite3 db/app.db ".backup 'backup/app.db.$(date +%F)'"`（在线安全备份，勿直接 cp 活动库） | 停后端 → 替换文件 → 启动 |
| `.env`（`DB_FIELD_KEY`） | 变更时 | 离线加密存档，双人保管 | 丢失=历史密文不可解密，只能重新入库 |
| `data/corpus/` | 变更时 | 随代码仓库/对象存储 | 重新执行第 4 章入库 |
| `db/faiss.index` | 无需 | 可由 DB 自动重建 | 删除即可，下次启动重建 |
| 前端 `dist/` | 每次发布 | 制品库 | 重新 `npm run build` |

恢复演练建议每季度一次：备份 → 删库 → 恢复 → 健康检查 → 抽一个素材分块预览验证解密。

## 8. 常见故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 登录后立刻退出 / 全站 401 | JWT_SECRET 变更或令牌过期 | 重新登录；多实例部署须统一 JWT_SECRET |
| 检索命中率 0 或结果异常 | FAISS 索引陈旧（DB 重建后） | M5 已加签名自动重建；仍异常时删 `db/faiss.index`+`faiss_meta.json` 重启 |
| `InvalidToken`/解密报错 | DB_FIELD_KEY 与建库时不一致 | 用建库时的 `.env`；确认未误用演示密钥 |
| 前端页面空白、控制台 404 `/api/...` | 前端走了真实模式但后端未启 / VITE_USE_MOCK=false 配错 | 确认后端 8000 存活；演示环境可设 `VITE_USE_MOCK=true` |
| SSE 生成无进度、最后一次性出现 | Nginx `proxy_buffering` 未关 | 按 6.1 配置 |
| 端口占用（8000/5173） | 旧进程未退出 | `lsof -i:8000` / `netstat -ano \| findstr 8000`，kill 后重启 |
| `ModuleNotFoundError: cryptography/faiss/...` | 依赖未装或装错环境 | `pip install -r api/requirements.txt`；确认 venv 已激活 |
| BGE 下载卡住/超时 | HF 网络 | 设 `HF_ENDPOINT=https://hf-mirror.com`；或保持 `EMBEDDING_BACKEND=offline` |
| 素材搜索只能搜标题 | 离线模式预期行为（content 加密无法 LIKE） | 接 BGE 后语义检索覆盖正文 |
| 领域筛选点选空白 | DOMAINS 与库内数据不一致 | 前端 `DOMAINS` 为唯一真源；新领域需补语料并重跑第 4 章 |

## 9. 升级流程

1. **前置**：备份 `db/app.db` 与 `.env`（见第 7 章）；记录当前 `git` 版本。
2. **拉代码**：`git pull`，前后端分别 `npm install` / `pip install -r api/requirements.txt`（有变更时）。
3. **数据迁移**（如有 schema 变更）：先停后端 → 备份 → 执行迁移脚本 → `clean_chunk.py --reset` 重建语料与索引 → 启动。
4. **验证**：健康检查 → 登录 → 六大页面冒烟 → 跑 `api/eval_retrieval.py` 确认命中率未回归（M5 基线 100%）。
5. **回滚**：恢复备份库 + 上一版本代码，重复第 4 步。

## 10. 安全清单（生产必做）

- [ ] 修改 `JWT_SECRET` 为强随机值（≥32 字节），多实例统一
- [ ] `CORS_ORIGINS` 收敛为实际前端域名（不用 `*`）
- [ ] 修改演示账号 `demo_seed` 口令或禁用该账号
- [ ] `.env` 权限 600、不入 Git；`DB_FIELD_KEY` 离线备份
- [ ] Nginx 启用 HTTPS（证书 + 80 跳转），`proxy_set_header X-Forwarded-Proto https`
- [ ] 后端仅绑定 `127.0.0.1`，对外经 Nginx 反代（勿直接暴露 8000）
